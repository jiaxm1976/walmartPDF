## 架构设计

### 数据库ER关系图

```
┌─────────────────────────────────────┐
│         PDFFile                     │  (PDF文件主表)
│  id, filename, file_hash ...        │
└─────────────────────────────────────┘
           │ 1:1 关系 (级联删除)
    ┌──────┴──────────────────────────┐
    │                                 │
    ▼                                 ▼
┌──────────────────┐    ┌──────────────────────┐
│ StatementHeader  │    │  SalesDetail         │
│ start_date...    │    │  product_price...    │
└──────────────────┘    └──────────────────────┘
    
    ┌──────────────────────────────────────────┐
    │ RefundDetail | AdjustmentDetail          │
    │ WFSDetail | OtherActivityDetail          │
    │ StatementFooter | PaymentDetail          │
    └──────────────────────────────────────────┘
```

### 数据生命周期

```
1. PDF上传
   ↓
2. PDFFile记录创建 (status=pending)
   ↓
3. PDF解析流程启动 (status=processing)
   ↓
4. 8个明细表并发插入数据
   ↓
5. 解析完成 (status=success/failed)
   ↓
6. 数据可用于查询、修改、导出、分析
   ↓
7. 数据备份和存档
```

## 表结构详解

### 1. pdf_files - PDF文件主表

**用途**: 存储PDF文件元数据和处理状态

| 字段 | 类型 | 约束 | 说明 |
|-----|------|------|------|
| id | INTEGER | PRIMARY KEY | 自增主键 (自动) |
| filename | VARCHAR(255) | NOT NULL, INDEX | 系统生成的文件名 (20251220_xxxx.pdf) |
| original_filename | VARCHAR(255) | NOT NULL | 用户上传的原始文件名 |
| file_path | VARCHAR(500) | NOT NULL | 文件存储的完整路径 |
| file_size | INTEGER | NOT NULL | 文件大小(字节, 范围0-2GB) |
| file_hash | VARCHAR(64) | NOT NULL, UNIQUE | SHA256哈希值(用于重复检测) |
| upload_time | DATETIME | NOT NULL | 用户上传时间 |
| process_status | ENUM | NOT NULL, INDEX | 处理状态 (4种): pending/processing/success/failed |
| process_time | DATETIME | NULL | 完成处理的时间戳 |
| error_message | TEXT | NULL | 处理失败的错误描述 |
| created_at | DATETIME | NOT NULL | 数据库记录创建时间 |
| updated_at | DATETIME | NOT NULL | 数据库记录最后修改时间 |

**索引定义**:
```sql
CREATE INDEX ix_pdf_files_filename ON pdf_files(filename);
CREATE INDEX ix_pdf_files_file_hash ON pdf_files(file_hash);
CREATE INDEX ix_pdf_files_process_status ON pdf_files(process_status);
```

**示例数据**:
```json
{
  "id": 1,
  "filename": "20251220_test001.pdf",
  "original_filename": "statement_2024.pdf",
  "file_path": "/path/to/pdf/20251220_test001.pdf",
  "file_size": 512000,
  "file_hash": "a1b2c3d4e5f6...",
  "upload_time": "2025-12-20T10:00:00",
  "process_status": "success",
  "process_time": "2025-12-20T10:05:00",
  "error_message": null
}
```

### 2. statement_header - 对账单头部

**用途**: 存储对账单的基本信息和期初期末数据

| 字段 | 类型 | 约束 | 说明 |
|-----|------|------|------|
| id | INTEGER | PRIMARY KEY | 自增主键 |
| pdf_file_id | INTEGER | NOT NULL, FK | 关联的PDF文件ID (级联删除) |
| start_date | DATE | NOT NULL, INDEX | 对账单周期开始日期 |
| end_date | DATE | NOT NULL | 对账单周期结束日期 |
| opening_balance | DECIMAL(15,2) | NULL | 期初余额 (精度到分) |
| reserve_funds | DECIMAL(15,2) | NULL | 备用金/预留资金 |
| awaiting_payment | DECIMAL(15,2) | NULL | 待结算/待付款金额 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

**约束**:
```sql
FOREIGN KEY (pdf_file_id) REFERENCES pdf_files(id) ON DELETE CASCADE
CREATE INDEX ix_statement_header_start_date ON statement_header(start_date)
```

**字段说明**:
- `start_date` 和 `end_date` 定义了一个完整的对账单周期
- 所有DECIMAL字段保留2位小数，用于精确的金融计算
- 级联删除: 删除PDF时自动删除所有关联的对账单头部记录

### 3. sales_detail - 销售明细

**用途**: 存储对账单中的销售相关数据

| 字段 | 类型 | 值范围 | 说明 |
|-----|------|--------|------|
| id | INTEGER | 自增 | 主键 |
| pdf_file_id | INTEGER | FK | 关联PDF文件 |
| product_price | DECIMAL(15,2) | 可为负 | 产品销售价格 |
| shipping | DECIMAL(15,2) | ≥0 | 运输/物流费用 |
| wfs_shipping_refund | DECIMAL(15,2) | ≤0 | WFS运输退款(通常为负) |
| net_tax_collected | DECIMAL(15,2) | ≥0 | 收取的税款净额 |
| net_commission | DECIMAL(15,2) | ≤0 | 沃尔玛佣金(通常为负) |
| withholding_tax | DECIMAL(15,2) | ≤0 | 代扣税款(通常为负) |
| wfs_shipping_tax_refund | DECIMAL(15,2) | ≤0 | WFS运输税退款 |
| walmart_funded_savings | DECIMAL(15,2) | ≥0 | 沃尔玛补贴/节余 |
| total | DECIMAL(15,2) | 任意 | 销售小计(可正可负) |
| other_total | DECIMAL(15,2) | - | 其他小计 |
| created_at | DATETIME | - | 创建时间 |
| updated_at | DATETIME | - | 更新时间 |

**计算公式**:
```
total = product_price + shipping + wfs_shipping_refund 
      + net_tax_collected + net_commission + withholding_tax 
      + wfs_shipping_tax_refund + walmart_funded_savings
```

## 关系和约束

### 外键关系

```sql
-- StatementHeader
ALTER TABLE statement_header
ADD CONSTRAINT fk_statement_header_pdf_file
FOREIGN KEY (pdf_file_id) REFERENCES pdf_files(id)
ON DELETE CASCADE;

-- SalesDetail (同样的模式应用到所有8个明细表)
ALTER TABLE sales_detail
ADD CONSTRAINT fk_sales_detail_pdf_file
FOREIGN KEY (pdf_file_id) REFERENCES pdf_files(id)
ON DELETE CASCADE;
```

### 约束类型

| 约束类型 | 说明 | 举例 |
|---------|------|------|
| PRIMARY KEY | 表的主键，唯一且非空 | id INTEGER PRIMARY KEY |
| NOT NULL | 字段必须有值 | filename VARCHAR NOT NULL |
| FOREIGN KEY | 引用另一表的键 | pdf_file_id REFERENCES pdf_files(id) |
| UNIQUE | 字段值必须唯一 | file_hash VARCHAR UNIQUE |
| DEFAULT | 默认值 | created_at DATETIME DEFAULT CURRENT_TIMESTAMP |
| CHECK | 值范围检查 | file_size > 0 |

### 数据完整性

**1. 参照完整性**
- 删除PDF记录时，自动删除所有8个明细表的关联数据
- 防止孤立记录存在

**2. 实体完整性**
- 每条记录都有唯一的主键ID
- 主键自动生成，无需手动指定

**3. 域完整性**
- DECIMAL(15,2): 确保金额精度
- DATE: 日期格式统一
- ENUM: 限制状态值
- NOT NULL: 必填字段验证

## 索引和性能

### 建立的索引

| 索引名 | 表名 | 字段 | 目的 | 查询例子 |
|-------|------|------|------|---------|
| ix_pdf_files_filename | pdf_files | filename | 快速查找文件 | WHERE filename = '20251220_test.pdf' |
| ix_pdf_files_file_hash | pdf_files | file_hash | 检测重复上传 | WHERE file_hash = 'abc123...' |
| ix_pdf_files_process_status | pdf_files | process_status | 按状态筛选 | WHERE process_status = 'success' |
| ix_statement_header_start_date | statement_header | start_date | 日期范围查询 | WHERE start_date BETWEEN '2024-01-01' AND '2024-12-31' |

### 查询优化建议

**1. 有效的日期范围查询**
```sql
-- ✅ 使用索引 (快速)
SELECT * FROM statement_header 
WHERE start_date >= '2024-01-01' 
  AND end_date <= '2024-12-31';

-- ❌ 不使用索引 (较慢)
SELECT * FROM statement_header 
WHERE YEAR(start_date) = 2024;
```

**2. 使用索引获取处理完成的文件**
```sql
-- ✅ 使用索引 (快速)
SELECT * FROM pdf_files 
WHERE process_status = 'success'
ORDER BY created_at DESC;
```

**3. JOIN查询优化**
```sql
-- ✅ 关联查询(有索引支持)
SELECT pf.id, pf.filename, sh.start_date, sd.total
FROM pdf_files pf
JOIN statement_header sh ON pf.id = sh.pdf_file_id
JOIN sales_detail sd ON pf.id = sd.pdf_file_id
WHERE sh.start_date >= '2024-01-01'
ORDER BY sh.start_date DESC;
```

### 性能指标

- **查询速度**: <200ms (平均)
- **并发连接**: SQLite支持1并发写
- **数据库大小**: 每条对账单约2KB
- **索引大小**: 约占主表大小的5-10%

## 常见操作

### 查询操作

#### 1. 统计对账单数量
```sql
-- 所有对账单
SELECT COUNT(*) as total_count FROM pdf_files;

-- 成功处理的对账单
SELECT COUNT(*) as success_count 
FROM pdf_files 
WHERE process_status = 'success';

-- 按状态统计
SELECT process_status, COUNT(*) as count
FROM pdf_files
GROUP BY process_status;
```

#### 2. 查询特定日期范围的对账单
```sql
SELECT sh.start_date, sh.end_date, sd.total, rd.total
FROM statement_header sh
LEFT JOIN sales_detail sd ON sh.pdf_file_id = sd.pdf_file_id
LEFT JOIN refund_detail rd ON sh.pdf_file_id = rd.pdf_file_id
WHERE sh.start_date >= '2024-01-01' 
  AND sh.end_date <= '2024-12-31'
ORDER BY sh.start_date DESC;
```

#### 3. 计算总销售额和总退款
```sql
SELECT 
  SUM(sd.total) as total_sales,
  SUM(rd.total) as total_refund,
  SUM(sd.total) + SUM(rd.total) as net_revenue
FROM sales_detail sd, refund_detail rd
WHERE sd.pdf_file_id = rd.pdf_file_id;
```

#### 4. 查找异常数据
```sql
-- 查找净收入为负的对账单
SELECT pf.id, pf.filename, sh.start_date,
  (sd.total + rd.total + wd.total) as net_revenue
FROM pdf_files pf
JOIN statement_header sh ON pf.id = sh.pdf_file_id
JOIN sales_detail sd ON pf.id = sd.pdf_file_id
JOIN refund_detail rd ON pf.id = rd.pdf_file_id
JOIN wfs_detail wd ON pf.id = wd.pdf_file_id
WHERE (sd.total + rd.total + wd.total) < 0;
```

## 故障排查

### 问题1: 数据库文件损坏

**症状**: 无法连接数据库或查询失败

**解决方案**:
```bash
# 步骤1: 列出备份
cd backend
python scripts/db_backup.py --list

# 步骤2: 恢复最近的备份
python scripts/db_restore.py --latest --force

# 步骤3: 验证恢复成功
python scripts/db_init.py --verify
```

### 问题2: 数据库空间不足

**症状**: 插入或更新操作失败

**解决方案**:
```bash
# 步骤1: 检查数据库大小
ls -lh backend/data/walmart_pdf_parser.db

# 步骤2: 删除失败的处理记录
sqlite3 backend/data/walmart_pdf_parser.db "DELETE FROM pdf_files WHERE process_status = 'failed';"

# 步骤3: 数据库整理
sqlite3 backend/data/walmart_pdf_parser.db "VACUUM;"

# 步骤4: 验证
ls -lh backend/data/walmart_pdf_parser.db
```

### 问题3: 查询性能下降

**症状**: 查询速度变慢

**解决方案**:
```bash
# 步骤1: 重建索引
sqlite3 backend/data/walmart_pdf_parser.db "REINDEX;"

# 步骤2: 分析表统计
sqlite3 backend/data/walmart_pdf_parser.db "ANALYZE;"

# 步骤3: 整理碎片
sqlite3 backend/data/walmart_pdf_parser.db "VACUUM;"
```

## Phase 4 数据分析相关查询

### 汇总统计查询

```sql
-- 获取指定日期范围的汇总数据
SELECT 
  COUNT(DISTINCT pf.id) as statement_count,
  SUM(sd.total) as total_sales,
  SUM(rd.total) as total_refund,
  SUM(sd.net_commission) as total_commission,
  SUM(wd.total) as total_wfs_fee,
  SUM(oad.walmart_product_ads) as total_ads_cost,
  (SUM(sd.total) + SUM(rd.total) + SUM(sd.net_commission) 
   + SUM(wd.total) + SUM(oad.walmart_product_ads)) as net_revenue
FROM pdf_files pf
JOIN statement_header sh ON pf.id = sh.pdf_file_id
LEFT JOIN sales_detail sd ON pf.id = sd.pdf_file_id
LEFT JOIN refund_detail rd ON pf.id = rd.pdf_file_id
LEFT JOIN wfs_detail wd ON pf.id = wd.pdf_file_id
LEFT JOIN other_activity_detail oad ON pf.id = oad.pdf_file_id
WHERE sh.start_date >= '2024-01-01' 
  AND sh.end_date <= '2024-12-31'
  AND pf.process_status = 'success';
```
