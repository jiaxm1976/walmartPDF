# 代码模板库

> **用途**: 提供标准化的代码模板，确保代码风格一致
> **更新**: 2025-12-16

---

## 📁 模板列表

### 1. function-template.py
**用途**: 函数编写模板

**包含内容**:
- 文件头注释标准格式
- 超详细的函数docstring示例
- 类型注解使用方法
- 参数验证示例
- 错误处理示例
- 日志记录示例
- 使用示例代码

**适用场景**:
- 编写新的service函数
- 编写新的util函数
- 需要详细注释的复杂函数

---

### 2. test-template.py
**用途**: 单元测试编写模板

**包含内容**:
- pytest fixture使用示例
- 正常情况测试（Happy Path）
- 边界情况测试（Edge Cases）
- 异常情况测试（Exceptions）
- 参数化测试（Parametrized）
- 性能测试（Performance）

**测试覆盖**:
- ✅ 正常情况：2-3个测试
- ✅ 边界情况：5-6个测试
- ✅ 异常情况：6-7个测试
- ✅ 参数化测试：1个（多场景）
- ✅ 性能测试：1个（可选）

**适用场景**:
- 为新函数编写测试
- 提升测试覆盖率
- 补充边界和异常测试

## 🎯 如何使用这些模板

### 方法1: 直接复制
```bash
# 复制函数模板
cp .claude/templates/function-template.py backend/app/services/new_service.py

# 复制测试模板
cp .claude/templates/test-template.py backend/tests/unit/test_new_service.py
```

### 方法2: 参考编写
1. 打开模板文件查看示例
2. 按照模板格式编写自己的代码
3. 确保包含所有必需部分

### 方法3: 使用魔法咒语
直接向Claude说：
```
使用函数模板创建新函数 process_pdf
使用测试模板为 process_pdf 创建测试
```

## ✅ 模板使用检查清单

### 函数模板检查
```
□ 文件头注释完整（功能/作者/依赖）
□ 函数docstring完整（8个必需部分）
□ 类型注解完整（参数+返回值）
□ 参数验证（类型+范围）
□ 错误处理（明确的异常类型）
□ 日志记录（关键步骤）
□ 使用示例（至少2个）
□ 魔法数字有注释或常量
```

### 测试模板检查
```
□ 至少2个正常情况测试
□ 至少5个边界情况测试
□ 至少5个异常情况测试
□ 测试命名清晰（test_功能_场景）
□ 每个测试有详细docstring
□ 使用断言消息（assert x, "说明"）
□ 测试可独立运行（使用fixture）
□ 测试覆盖率>80%
```

## 📊 代码质量标准

### 函数质量
- **行数**: <50行（理想）
- **参数**: <5个（建议）
- **圈复杂度**: <10（必须）
- **注释比例**: >30%（文档注释）

### 测试质量
- **覆盖率**: >80%（核心函数）
- **测试数量**: ≥10个（每个函数）
- **测试分类**: 正常+边界+异常
- **断言数量**: ≥1个（每个测试）
